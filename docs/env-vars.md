# Environment Variables

| Variable | Where used | Target | Notes |
|---|---|---|---|
| `SSI_API_KEY` | `lib/graphql.ts`, `lib/ssi-auth.ts` (server-only) | Both | Sent as the `x-api-key` header on every upstream call. As of 2026-05 the API key alone is not sufficient -- a JWT is also required (see `SSI_SERVICE_EMAIL`/`PASSWORD`). Never use `NEXT_PUBLIC_` prefix. |
| `SSI_SERVICE_EMAIL` | `lib/ssi-auth.ts` (server-only) | Both | Email for the dedicated SSI bot account that backs every upstream request. SSI now requires a logged-in user (JWT obtained via `token_auth(email, password)`) on every GraphQL resolver. Use a dedicated bot account, never a real user. Never `NEXT_PUBLIC_`. |
| `SSI_SERVICE_PASSWORD` | `lib/ssi-auth.ts` (server-only) | Both | Password for the bot account. Set via `wrangler secret put`. Quote with single quotes in `.env.local` so shell `$`/`!` chars survive. Never `NEXT_PUBLIC_`. |
| `CACHE_PURGE_SECRET` | `app/api/admin/cache/purge/route.ts`, `app/api/admin/cache/health/route.ts`, `app/api/admin/auth/jwt/route.ts` | Both | Any strong random string; never `NEXT_PUBLIC_` |
| `MIN_CACHE_TTL_SECONDS` | `lib/match-ttl.ts` (server-only) | Both | Minimum TTL floor for all non-permanent cache entries. Default `30` (s) -- keeps active matches near-real-time so courtside polling picks up fresh scorecards within seconds. Raise it to reduce upstream load on shared deployments. Set to `0` to disable. Never `NEXT_PUBLIC_`. |
| `MATCH_COMPLETE_DAYS_SINCE` | `lib/match-ttl.ts` (server-only) | Both | Hard time gate (days) before a match can be permanently pinned to durable cache. Default `3`. Even SSI flag flips (`status=cp`, `results=all`) cannot pin earlier than this -- protects against the Skepplanda-style premature pinning bug where a mid-match flag flip caused stale data to stick. Raise for events with very long scoring tails (e.g. World Shoots that run 5+ days). Never `NEXT_PUBLIC_`. |
| `MATCH_COMPLETE_SCORING_PCT` | `lib/match-ttl.ts` (server-only) | Both | Scoring threshold (percent, 0-100) for the un-flagged completion heuristic. Default `98`. Used only when SSI never flips `status=cp`/`results=all` and the time gate has passed. Lower values pin more matches earlier (saves upstream calls) at the risk of catching matches still accruing scorecards. Never `NEXT_PUBLIC_`. |
| `MATCH_PROBE_ENABLED` | `lib/graphql.ts` (server-only) | Both | Kill switch for the match-level "if-modified-since" probe (`refreshCachedMatchQuery`). Default on. Set to `off` to disable the probe and fall back to always-refetch SWR behaviour. Use this if telemetry shows `IpscMatchNode.updated` doesn't track scorecard activity (e.g. only bumps on match-level admin edits, not per-scorecard saves). Never `NEXT_PUBLIC_`. |
| `MATCH_PROBE_MAX_SKIP_AGE_SECONDS` | `lib/graphql.ts` (server-only) | Both | Belt-and-braces ceiling: even when the probe says "no change", never skip a refetch if the last full fetch is older than this many seconds. Default `900` (15 min; raised from 300 in the 2026-08-15 SSI-load redesign -- the probe now carries per-stage scoring_progress, so the full refetch is only a drift safety net). Never `NEXT_PUBLIC_`. |
| `SCORECARDS_DELTA_ENABLED` | `lib/scorecards-archive.ts` (server-only) | Both | Opt-in for the `scorecards(updated_after:)` delta path on CHANGED stages, watermarked by `latest_scorecard_update` minus a 3s overlap. Default **off**; SSI confirmed semantics 2026-08-18 and the marker was verified live 2026-08-19 -- flip on in staging first, then prod. When off, changed stages are refetched whole (still only the changed stages). Never `NEXT_PUBLIC_`. |
| `UPSTREAM_MAX_CONCURRENCY` | `lib/upstream-limiter.ts` (server-only) | Both | Per-isolate semaphore for concurrent outbound SSI GraphQL calls; also sizes the (default-off) global lease pool. Default `2`. Never `NEXT_PUBLIC_`. |
| `UPSTREAM_GLOBAL_LEASES` | `lib/upstream-limiter.ts` (server-only) | Both | `on` enables Redis slot leases intended to cap upstream concurrency across instances. **Default off** -- they hung requests in production twice (2026-08-20: 27 cancelled tasks and 2 user-visible 500s under 12 concurrent pollers) because the wait is paid per upstream call and a fan-out pays it repeatedly. Read the comment in `lib/upstream-limiter.ts` before turning this on. Never `NEXT_PUBLIC_`. |
| `UPSTREAM_GLOBAL_WAIT_MS` | `lib/upstream-limiter.ts` (server-only) | Both | How long a *single* upstream call polls for a global Redis slot before proceeding anyway (fail-open). Default `800`. `0` disables waiting (claim-or-proceed). **Keep this small** -- the budget is paid per call, so a large per-stage fan-out multiplies it; a 10000 default hung whole requests until the Workers runtime cancelled them (2026-08-20). Never `NEXT_PUBLIC_`. |
| `SSI_UPSTREAM_PAUSED` | `lib/upstream-pause.ts` (server-only) | Both | Emergency kill switch: any value except `off`/`0`/`false` blocks ALL outbound SSI calls before network I/O; cached data serves via stale-on-error. Set/unset via `wrangler secret` -- no redeploy needed. Never `NEXT_PUBLIC_`. |
| `SCORECARDS_DELTA_MAX_AGE_SECONDS` | `lib/graphql.ts` (server-only) | Both | Reconcile interval (seconds): even when delta merges succeed, force a periodic full refetch to self-heal from drift the delta cannot detect (upstream deletions, new stages, subtle merge bugs). Default `600` (10 min). Lower for more aggressive self-healing during high-stakes events. Never `NEXT_PUBLIC_`. |
| (admin) `POST /api/admin/cache/force-refresh?ct=&id=` | `app/api/admin/cache/force-refresh/route.ts` | Both | Recovery lever: sets a `force-refresh:{ct}:{id}` Redis sentinel that bypasses probe / delta on the next SWR cycle. Requires `Authorization: Bearer <CACHE_PURGE_SECRET>`. Sentinel auto-clears after a successful full refresh; auto-expires after 5 min. |
| (admin) `DELETE /api/admin/auth/jwt` | `app/api/admin/auth/jwt/route.ts` | Both | Drops the cached SSI JWT (`ssi:jwt:v1`) so the next upstream call re-mints via `token_auth`. Use after changing the bot's permissions on SSI -- club-membership-driven access has been observed not to propagate to in-flight tokens. Requires `Authorization: Bearer <CACHE_PURGE_SECRET>`. |
| `CACHE_TELEMETRY` | `lib/telemetry.ts` (server-only) | Both | Set to `off` to suppress all telemetry. Default on -- emits one JSON line per event via `console.info` (picked up by Cloudflare Workers Logs / Docker stdout) and additionally writes to R2 on Cloudflare when the `TELEMETRY` binding is bound. Never `NEXT_PUBLIC_`. |
| `TELEMETRY_SAMPLE_<DOMAIN>` | `lib/telemetry-sinks-cf.ts` (Cloudflare only) | Cloudflare only | Per-domain sample rate, value in `[0, 1]`. `1` keeps every event, `0` drops everything, `0.1` keeps 10%. All domains (`cache`, `upstream`, `error`, `ai`, `d1`, `background`, `usage`) default to `1` -- at current ~3-6k requests/day even the highest-volume `usage` domain stays under 2% of the R2 free-tier cap. The `upstream` domain includes `status-checked` events from the homepage banner poll (every 30s per active client) -- set `TELEMETRY_SAMPLE_UPSTREAM=0.1` if active-client volume grows enough to push that domain past the cap. Set e.g. `TELEMETRY_SAMPLE_USAGE=0.1` if traffic grows ~10x. Never `NEXT_PUBLIC_`. |
| `NEXT_PUBLIC_BUILD_ID` | `components/update-banner.tsx`, `app/api/version/route.ts` | Both | Git SHA baked into the client bundle at Docker build time; powers new-version detection. Auto-injected by `pnpm docker:build`. Unset in `pnpm dev` -- version check is skipped. |
| `REDIS_URL` | `lib/cache-node.ts` | Docker only | `redis://localhost:6379` locally, `rediss://...` for managed Redis. Not needed for CF builds. |
| `SHOOTER_DB_PATH` | `lib/db-sqlite.ts` | Docker only | Path to SQLite database file. Defaults to `./data/shooter-index.db`. Not needed for CF builds. |
| `CACHE_KEY_PREFIX` | `lib/cache-node.ts`, `lib/cache-edge.ts` | Both | Optional namespace prefix prepended to every Redis key. Useful when sharing one Redis instance across multiple deployments. Default empty. Never `NEXT_PUBLIC_`. |
| `UPSTASH_REDIS_REST_URL` | `lib/cache-edge.ts` | Cloudflare only | REST URL from Upstash console. Set via `wrangler secret put` in production. |
| `UPSTASH_REDIS_REST_TOKEN` | `lib/cache-edge.ts` | Cloudflare only | REST token from Upstash console. Set via `wrangler secret put` in production. |
| `MCP_SECRET` | `app/api/mcp/route.ts` | Both | Optional. If set, `POST /api/mcp` requires `Authorization: Bearer <MCP_SECRET>`. Omit for public access. |
| `EXTERNAL_API_TOKENS` | `lib/api-v1.ts` (server-only) | Both | Comma-separated bearer tokens that gate `/api/v1/*` (the public, version-locked surface used by external consumers like splitsmith). If unset or empty, every v1 request returns `401 unauthorized`. Generate with `python -c "import secrets; print(secrets.token_urlsafe(32))"`. Rotate by appending the new token, rolling consumers, then removing the old one -- see `docs/api-v1.md`. Never `NEXT_PUBLIC_`. |
| `EXTERNAL_API_RATE_LIMIT_PER_MIN` | `lib/api-v1.ts` (server-only) | Both | Per-token rate limit (req/min) for `/api/v1/*`. Default `60`. Set to a higher integer to relax. Bucket is fixed-window, keyed by SHA-256 hash of the token (raw token never lands in Redis). Never `NEXT_PUBLIC_`. |
| `NEXT_PUBLIC_APP_URL` | `app/layout.tsx` (`metadataBase`), `app/api/mcp/route.ts`, `app/match/[ct]/[id]/layout.tsx` | Both | Base URL used by `metadataBase` (absolute OG/twitter image URLs), MCP tools, and OG image meta tags. Defaults to `http://localhost:PORT`. Inlined at build time -- the Cloudflare deploy workflows set it per environment (prod: `https://scoreboard.urdr.dev`, staging: the workers.dev URL). |
| `AI_PROVIDER` | `lib/ai-provider.ts` (server-only) | Both | `"cloudflare"` or `"openai"`. Omit to disable AI coaching tips. Never `NEXT_PUBLIC_`. |
| `AI_MODEL` | `lib/ai-provider.ts` (server-only) | Both | Model identifier, e.g. `"gpt-4o-mini"` or `"@cf/meta/llama-3.1-8b-instruct"`. Never `NEXT_PUBLIC_`. |
| `AI_API_KEY` | `lib/ai-provider.ts` (server-only) | Both | API key/token for the AI provider. **Optional for `cloudflare` provider** -- omit to use the Workers AI binding (`env.AI`) instead of the REST API. Never `NEXT_PUBLIC_`. |
| `AI_API_URL` | `lib/ai-provider.ts` (server-only) | Both | Base URL. Required for Cloudflare Workers AI. Defaults to `https://api.openai.com/v1` for `openai`. |
| `SMITHERY_API_KEY` | `.github/workflows/smithery-publish.yml` | CI only | Smithery registry API key. Store as a GitHub `production` environment secret. Obtain from https://smithery.ai/account/api-keys. Never `NEXT_PUBLIC_`. |
